# M001: Discoverable tool bundles

## Goal

Replace the flat, hardcoded verification-runner inventory with configurable,
discoverable category and tool bundles while preserving framework ownership of
runner implementations.

## Scope

1. Define category and tool manifests plus ordered project tool assignments.
2. Add category verify/fix entry points and aggregate orchestration.
3. Add `toolctl.py` discovery, enablement, status, defaults, and cleanup commands.
4. Add concise latest-run logging for verification and Docker builds.
5. Add explicit bootstrap profiles, beginning with `generic`, and seed thin
   project wrappers.
6. Update contracts, templates, documentation, and tests.

Tool dependencies, profile inheritance, scaffold migrations, and project-local
custom categories remain future topics.

## Completion criteria

- Category and tool inventories are manifest-driven.
- Verification follows configured category and tool order and continues after
  individual failures.
- The accepted `toolctl.py` interface is covered by focused tests.
- `--profile generic` creates the minimal project with the agreed default tools.
- Host-side tests pass; the unavailable Docker gate is reported in handover.
